# AI disclosure

Pindu launcher is written almost entirely with AI assistance. Of the 234 commits in its history (merge commits left
out), 208 (89%) are AI-assisted, and they hold 95% of the lines ever changed. A person wrote a small set of files
without AI, listed [below](#written-by-a-person-without-ai), most importantly the development Flatpak manifest that
the Flathub manifest will be based on. The maintainer, Tim van Oudheusden, decides what is built, reviews the work and
is responsible for everything in this repository.

The numbers here were measured at commit `d80d407` (2026-11-17). [How they are measured](#how-the-numbers-are-measured)
explains the method and the command that repeats it.

## What AI is used for

- **Planning**: the main spec and the research documents in `docs/` (the `*.pdf` files) are AI-assisted (deep
  research and drafting), and the GitHub issues generated from the spec count as AI-assisted planning.
- **Product analysis and workstream specs**: [`docs/product-analysis.md`](docs/product-analysis.md) is AI-written:
  an analysis by OpenAI's model, reviewed and revised against the repository by Claude, as its front matter says. The
  maintainer took its decisions (section 14) on 2026-11-19. The workstream spec pages drawn from it and from the
  issues (`docs/game-identity.md`, `docs/library-health.md`, `docs/diagnostics.md`, `docs/controller-parity.md`,
  `docs/shelves-and-metadata.md`, `docs/launch-outcomes.md`, `docs/save-snapshots.md`,
  `docs/accessibility-polish.md`) are AI-written by Claude Code (#550).
- **Code**: the Rust crates, the Blueprint UI, the GSettings, desktop and D-Bus files, the CSS and the fullscreen
  designs.
- **Tests**: unit, integration and end-to-end tests, and the test fixtures.
- **CI and tooling**: the GitHub Actions workflows, the scripts in `scripts/` and `build-aux/`, and the repository's
  governance files (rulesets, risk tiers, policies, templates).
- **Packaging**: the release and development Flatpak manifests after their hand-written start, the RPM and DEB recipes,
  the COPR, AUR and nixpkgs recipes and the release workflows. The Flathub manifest gets no AI assistance (see below).
- **Documentation**: the README, the contributor, security and translation guides, the runbooks, the agent
  instructions and the release notes.
- **Translations**: agents mark strings for translation and regenerate the template `po/pindu-launcher.pot`. The
  translations themselves come from people in Weblate.
- **Agents working on their own**: Claude Code in CI and Hive's agents (the `hive-worker-bee` GitHub App) take issues
  and open pull requests. The maintainer's own commits are made in sessions with CLI agents (Claude Code and others).
  How they work together is in [`docs/multi-agent.md`](docs/multi-agent.md).

The app itself calls no AI model.

## How AI-written work is reviewed

- **Pull requests only**: `main` is protected by a ruleset (`.github/rulesets/main.json`); no agent can push to it,
  and every change lands through a pull request that fixes an issue.
- **CI gates**: every pull request runs formatting, Clippy with warnings as errors, documentation, the Rust and Meson
  test suites, coverage floors, script tests, the Flatpak build and Flathub's linter
  (`.github/workflows/ci.yml`, `.github/workflows/coverage-gate.yml`). Code changes are written test-first.
- **Risk tiers**: every pull request is classified as low, medium or high risk from the paths it changes
  ([`docs/risk-tiers.md`](docs/risk-tiers.md)), and a review rubric checks its tests and gates.
- **Merge queue and maintainer review**: the merge queue merges a low- or medium-risk pull request once every check
  passes. A high-risk one (workflows, scripts, build and packaging files, the MetaInfo, dependencies, agent
  instructions) waits for the maintainer, who reviews the full diff and merges it by hand; `.github/CODEOWNERS`
  requests his review.
- **Trust boundaries**: [`docs/security/SECURITY-AI.md`](docs/security/SECURITY-AI.md) sets what agents may never do,
  such as granting the Flatpak more permissions or touching the Flathub manifest.
- **Audit trail**: [`docs/ai-ops-runbook.md`](docs/ai-ops-runbook.md) explains how agent work is watched, paused and
  undone.

## How the numbers are measured

Run, from a full clone with the GitHub CLI signed in:

```sh
gh pr list --state merged --limit 1000 --json number,author,headRefName,body | scripts/ai-extent.sh
```

[`scripts/ai-extent.sh`](scripts/ai-extent.sh) goes through every commit that is not a merge commit and sorts it into
the first class that fits:

1. **Person, no AI**: the commit is listed in `scripts/lib/person-commits.txt`, which only the maintainer edits.
2. **Weblate** or **Dependabot**: the commit's author is Weblate (or a translator's Weblate account) or Dependabot.
3. **AI, marked**: the commit has a `Co-authored-by:` trailer naming an AI model, or a `Hive-Run:` trailer; or Hive's
   App wrote it; or it came in through a pull request that [`scripts/lib/pr-source.jq`](scripts/lib/pr-source.jq)
   calls agent work, or whose description says an AI agent wrote it.
4. **AI, unmarked**: the maintainer's own commit without a mark, made in a CLI-agent session.
5. **Other**: anyone else. No commit falls here yet.

Classes 3 and 4 are AI-assisted. For every part, the script counts the commits and the added plus deleted lines
(`git log --numstat`) in each class, and the share of the part's current lines that `git blame` gives to a class 1
commit. Pass `--rev <commit>` to measure an older commit. Re-run it before a release or a Flathub submission and
update the tables here.

Limits: a commit counts fully towards each part it touches, however a person and an agent shared the work; lines
changed count work done, including code that was later rewritten; binary files count no lines.

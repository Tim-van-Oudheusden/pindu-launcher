# Reflections

Cross-session knowledge for work in this repository, by agents and people alike: short write-ups of what a session or
an incident taught that the next one should not have to rediscover. Read the newest few before starting work; add one
when a session uncovers something non-obvious about the code, the tooling, the Flatpak and GNOME SDK environment, the
launchers' data, or a release that went wrong.

A reflection explains a lesson; it is not a rule. When a lesson becomes a rule, encode it where contributors and agents
already look ([`AGENTS.md`](../../AGENTS.md), [`CONTRIBUTING.md`](../../CONTRIBUTING.md),
[`docs/releasing.md`](../releasing.md), or a test that fails when the rule is broken) and link that from the
reflection. Work still to do goes into a GitHub issue, never into a reflection.

## Format

One Markdown file per reflection, named `YYYY-MM-DD-short-slug.md`, with:

- **Context**: the issue or pull request, and what was being attempted.
- **What happened**: the surprise, failure or discovery, with the evidence (a command and its output, a CI run).
- **Lesson**: what to do differently, stated as guidance.
- **Encoded in**: where the lesson now lives, or "not yet" with a link to the follow-up issue.

Reflections are blameless: describe what happened and why, not who. Never put secrets, tokens or the contents of
another launcher's credential files in one. Add every new reflection to the index below, newest first, in the same pull
request.
